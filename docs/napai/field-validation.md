# 場域驗證：程序與紀錄表

「場域成效與使用者驗證」需要真人使用的證據。**這件事目前還沒做**；本頁提供可以在一天內完成的程序、紀錄表與統計方式。系統端的紀錄（延遲、工具成功率、回饋）會自動留存，可用工具匯出。

> 競賽辦法對使用者驗證的層級定義與要求的證據形式（例如前後比較、使用者回饋），請依官方文件核對後調整本頁的做法。

## 1. 要回答的問題

| # | 問題 | 怎麼量 |
|---|---|---|
| Q1 | 用了平台，學生是否更快找到「適合自己、還能報名」的競賽？ | 同一個任務，不用平台與用平台的完成時間、正確性 |
| Q2 | 助理給的理由（優點、弱項、缺口）學生看得懂、認同嗎？ | 5 點量表、開放意見 |
| Q3 | 推薦的隊友與老師，學生會不會真的去聯絡？ | 意願（是／否）與原因 |
| Q4 | 「按確認才執行」的設計，學生是否覺得掌握得住？ | 5 點量表 |
| Q5 | 系統穩不穩？ | 線上指標：完成率、延遲、降級率、工具成功率 |

## 2. 參與者與環境

| 項目 | 建議 |
|---|---|
| 人數 | 5–8 位，至少來自 3 個系所；有參賽經驗與沒有經驗的各半 |
| 每人時間 | 約 20 分鐘 |
| 環境 | 部署好的測試環境，已設定 Claude 金鑰；一位主持、一位記錄 |
| 帳號，做法 A（不涉及個資） | 每人指定一個示範帳號（虛構人物），請他把自己當成那位學生。優點：不蒐集任何個資；缺點：技能檔不是本人的，Q2、Q3 的效度較低 |
| 帳號，做法 B（本人資料） | 參與者自行註冊、勾選同意，填 5–8 門自己的修課成績與一兩項證照或作品。優點：推薦是針對本人的；缺點：會蒐集真實個資，需要告知並在結束後刪除 |
| 建議 | 時間允許時至少 3 位用做法 B；其餘用做法 A |

做法 B 的告知要點（口頭或書面皆可，留下紀錄）：蒐集的資料（成績、證照、作品、對話）；用途（本次測試）；會送到外部語言模型服務的內容（階級與可信狀態，不含姓名、學號、成績）；保存到何時（測試結束當天刪除）；可隨時退出。結束後請參與者在「我的檔案」刪除帳號，或由團隊重置資料庫。

## 3. 任務

每位參與者依序做三個任務。任務 1 先**不用平台**做一次當基準，再用平台做一次。

| 任務 | 基準（不用平台） | 使用平台 |
|---|---|---|
| T1 找競賽 | 給 5 分鐘，用搜尋引擎與學校網站，找出一個「你的技能適合、目前還能報名」的競賽，說出報名截止日與你缺什麼 | 在 AI 助理輸入自己的話（例如「我想參加比賽」），讀完結果後回答同樣的問題 |
| T2 找隊友 | 口頭回答：平常怎麼找跨系隊友？大概要多久？（只記錄，不實做） | 請助理找互補的隊友；看完後回答：哪一位你會邀請？為什麼？ |
| T3 找老師 | 口頭回答：平常怎麼找指導老師？ | 請助理推薦老師；看完後回答：你會聯絡嗎？聯絡前要確認什麼？ |

最後請參與者看「待確認動作」卡片，自己決定按確認或取消，並說明理由。

主持人不要示範操作，也不要提示該輸入什麼；參與者卡住超過 1 分鐘再給提示，並記錄「有提示」。

## 4. 紀錄表

紀錄表範本：[`field-validation-sheet.csv`](field-validation-sheet.csv)（一位參與者一列）。

| 欄位 | 說明 |
|---|---|
| 編號、系所、年級、有無參賽經驗 | 不記姓名與學號 |
| 帳號做法 | A 或 B |
| T1 基準：是否完成、秒數、答案是否正確 | 「正確」= 競賽確實存在、截止日與官方公告相符、確實還能報名 |
| T1 平台：是否完成、秒數、答案是否正確、有無提示 | 同上 |
| T2、T3：是否完成、是否願意聯絡、原因 | — |
| 待確認動作：確認／取消、原因 | — |
| 量表（1–5）：理由看得懂、推薦合理、掌握得住、願意再用 | 1 非常不同意，5 非常同意 |
| 開放意見 | 最有用的地方、最困擾的地方 |
| 觀察 | 主持人看到的問題：看不懂的字、找不到的按鈕、助理答非所問 |

請參與者在覺得有幫助或沒幫助的回覆下方按讚或倒讚（可留言），系統會記錄。

## 5. 統計方式

| 指標 | 算法 |
|---|---|
| T1 完成率（基準／平台） | 完成人數 ÷ 總人數 |
| T1 中位完成時間（基準／平台） | 只算完成者；人數少，用中位數並列出每個人的數值 |
| T1 正確率（基準／平台） | 答案正確人數 ÷ 完成人數 |
| 量表 | 每題的中位數與分布（幾人給 4 分以上） |
| 願意聯絡隊友／老師的比例 | 人數 ÷ 總人數，並列出不願意的原因 |
| 系統指標 | 匯出檔 `metrics.json` 的完成率、平均與最大延遲、降級率、工具成功率、讚與倒讚數 |

5–8 人的樣本只能做描述，不能做顯著性檢定；報告時列出人數與每個人的原始數值，不要只報平均。若平台比基準慢或錯，照實列出並說明原因。

## 6. 匯出系統紀錄

Demo 模式的資料庫在後端重啟時會重建。**每一場測試結束後、重啟之前**執行：

```bash
python3 backend/tools/export_validation.py --base https://<測試環境> --admin admin@example.edu --password <管理員密碼> --days 1 --out validation-out
```

| 輸出 | 內容 |
|---|---|
| `metrics.json` | 回合數、完成率、降級率、中止率、延遲、token 與估算成本、工具成功率、人工介入率、停止原因 |
| `feedback.csv` | 每一筆讚／倒讚與留言、該回覆的模式、耗時、工具呼叫數 |
| `sessions.csv` | 每個對話的回合數、依序呼叫的工具、動作的結果（確認／取消） |
| `trace-<id>.json` | 每個對話的操作軌跡；不含使用者的提問原文，其他學生為代號 |

留言欄是參與者自己寫的文字，繳交前請檢查有沒有個資。

## 7. 驗證紀錄的格式（繳交用）

| 段落 | 內容 |
|---|---|
| 驗證對象與日期 | 人數、系所分布、日期、地點、環境（模型版本、系統版本） |
| 方法 | 第 3 節的任務；帳號做法 A／B 各幾人；告知與同意的方式 |
| 結果 | 第 5 節的指標，基準與平台並列；每位參與者的原始數值表 |
| 使用者回饋 | 量表分布；開放意見的原文摘錄（去識別化）；讚與倒讚 |
| 發現的問題與處置 | 問題、嚴重程度、已修正或列入待辦 |
| 限制 | 樣本數、參與者來源、任務是否貼近真實情境 |
