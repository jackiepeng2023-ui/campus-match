## 4 和《軟體工程架構 3.1》不一樣的地方

| # | 項目 | 架構文件原本寫的 | 實作 | 為什麼 |
|---|---|---|---|---|
| 1 | 正式模式的啟動檢查 | 重建開關與時鐘開關都必須關閉 | JWT 密鑰是預設值就拒絕啟動；時鐘開關開著就拒絕；要重建而且資料庫已有學生帳號就拒絕，除非另外設 `APP_ALLOW_DESTRUCTIVE_RESET=true` | 正式模式的冒煙測試要對空的、可丟棄的資料庫重建 |
| 2 | 新成員看得到多少訊息 | 沒有寫 | 只看得到加入之後的訊息 | 隊伍可能在對方加入前討論過這位申請人【推論】 |
| 3 | 不在線上時 | 寫站內通知並送 APNs | 新訊息不寫站內通知，未讀數顯示在訊息分頁；離線只送 APNs「你有新訊息」 | 每則訊息一筆通知會把小鈴鐺洗掉 |
| 4 | 報名截止時還在招募的隊伍 | 一律結束 | 至少 2 人而且達到比賽的每隊下限，就以目前名單成隊；否則結束 | 已經湊到人的隊伍，不該因為沒按成隊就被結束 |
| 5 | 比賽沒有公告日期 | 沒有寫 | 隊伍的結束日先抓報名截止後 120 天（可調參數） | 否則報名一截止，群組就變唯讀 |
| 6 | 比賽結束後 | 自動結束隊伍 | 結束日後 1 天結束（2.0 是 7 天）；已標記報名的算完成，沒標記的算未完成 | 取代結案投票 |
| 7 | 標記已報名 | 只能標記 | 可以取消標記；還在招募時標記，等於同時成隊 | 按錯要能復原；少一個步驟 |
| 8 | 成員退出或被請離 | 沒有寫細節 | 成員資格直接刪除；隊伍已成隊而且還沒截止的話，回到招募中 | 空出來的名額要能再找人 |
| 9 | 提醒的天數 | 放在系統參數 | 7、3、1 寫在程式裡 | 先求簡單；要調再搬 |
| 10 | 鎖的順序 | 沒有寫 | 先隊伍列，再缺口與申請列，最後對話列 | 兩個請求同時進來不會互相卡死 |
| 11 | 遷移腳本 | 分多支 | 這一階段一支 `V3_1_0`；帳號、檢舉、封鎖、排序相關的欄位留給後面的里程碑 | 沒用到的欄位先不加 |
| 12 | 不符合條件的原因 | 沒有寫 | API 回的原因改成白話，不帶 G1–G4 代號 | 規格書第 11 節的友善標準 |
| 13 | 隊伍頁 | 成員與邀請放在群組的側欄 | 另外有一頁隊伍頁：看隊伍、申請、審核、推薦與邀請、成隊、解散；群組保留報名追蹤 | 還不是隊友的人也需要一個看隊伍的地方 |
| 14 | Demo 重置 | 沒有寫 | 重置期間排程暫停 | 重置中途資料表會暫時回到 2.0 的樣子 |
| 15 | 紀錄檔 | — | 不再把示範密碼寫進紀錄檔 | 密碼不該出現在紀錄裡 |

## 5 新增與修改的 API

| 方法與路徑 | 用途 | 誰可以用 |
|---|---|---|
| `POST /cases`（帶 `need`） | 開隊：比賽、隊名、還缺幾人、想找的技能、一句話 | 學生 |
| `GET /cases/wall` | 隊伍牆；`fit=true` 只看適合我，`mine=true` 看我的隊伍 | 登入者 |
| `POST /cases/{id}/form` | 提前成隊 | 隊長 |
| `POST /cases/{id}/leave` | 退出 | 成員，報名前 |
| `DELETE /cases/{id}/members/{userId}` | 請離 | 隊長，報名前 |
| `POST`、`DELETE /cases/{id}/registration` | 標記已報名、取消標記 | 隊長 |
| `GET /conversations` | 我的對話與未讀數 | 本人 |
| `GET /conversations/{id}` | 單一對話與成員 | 對話成員 |
| `GET /conversations/{id}/messages` | 讀訊息；`after` 補漏、`before` 往上翻 | 對話成員 |
| `POST /conversations/{id}/messages` | 送訊息；帶 `clientId` 重送不會重複 | 對話成員，非唯讀 |
| `POST /conversations/{id}/read` | 更新已讀位置 | 對話成員 |
| `GET /cases/{id}/conversation` | 隊伍群組的對話編號 | 隊伍成員 |
| `WS /ws` | 推送：`message.new`、`conversation.updated`、`engagement.updated`、`team.updated`、`notification.new` | 登入者 |

錯誤代碼新增：`ALREADY_IN_COMPETITION`、`COMPETITION_CLOSED`、`TEAM_TOO_SMALL`、`TEAM_TOO_LARGE`、`ROSTER_LOCKED`、`OWNER_CANNOT_LEAVE`、`READ_ONLY`、`RATE_LIMITED`（429）。

不是對話成員的人（包含管理員）讀寫對話，一律回 404，不透露對話是否存在【一手：實跑】。

## 9 怎麼跑

```bash
# 後端（Demo 模式，會重建示範資料）
cd backend && ./mvnw -DskipTests package
java -jar target/campus-match-1.0.0.jar                                       # http://localhost:8080；示範密碼的預設值見 README，可用 APP_DEMO_PASSWORD 更換

# 網頁開發（後端不在 8080 時用 VITE_PROXY_TARGET 指定）
cd web && npm install && npm run dev                                          # http://localhost:5173

# 更新 jar 內的網頁
cd web && npm run build && rm -rf ../backend/src/main/resources/static && cp -r dist ../backend/src/main/resources/static

# 測試（都會重置示範資料，只能對 Demo 模式的環境執行）
python3 backend/tools/fomo_e2e.py http://localhost:8080
node web/tools/fomo_ui.cjs http://localhost:8080 docs/3.1/screenshots
```

正式模式（`APP_SEED_MODE=reference`）必須設 `APP_JWT_SECRET`（32 字元以上的亂數）、`APP_DEMO_CLOCK=false`、`APP_RESET_ON_START=false`。
